# Working on LibRawWrapper.jl

## Purpose and structure

This package exposes LibRaw through two interfaces: `LibRawRaw` preserves the
generated C ABI, and `LibRawProcessor` provides a managed Julia API with owned
results. Keep those responsibilities distinct.

- `src/LibRawWrapper.jl`: module assembly and public exports.
- `src/raw.jl`: selects an ABI binding from `src/bindings/`.
- `src/types.jl`: high-level result types, enums, and validated rendering options.
- `src/highlevel.jl`: resource ownership, lifecycle, input, and working images.
- `src/snapshots.jl`: copied metadata; `src/sensor.jl`: sensor/CFA access.
- `src/processing.jl`: rendering and thumbnail extraction.
- `gen/`: Clang.jl generation from the matching `LibRaw_jll` headers.
- `docs/src/`: guide and API reference; `examples/`: runnable workflows.
- `TODO.md`: remaining features and intentional raw-only scope.

## Methodology and references

1. Read the relevant implementation and tests before changing behavior. Establish
   which lifecycle stages, native buffers, and output parameters are involved.
2. Verify native semantics against the [LibRaw C API](https://www.libraw.org/docs/API-C.html),
   [C++ API](https://www.libraw.org/docs/API-CXX.html),
   [data structures](https://www.libraw.org/docs/API-datastruct-eng.html), and
   [API notes](https://www.libraw.org/docs/API-notes.html). Check the installed
   `LibRaw_jll` headers/source when online documentation differs from the pinned
   library version. `Project.toml` is the authority for dependency compatibility.
3. Use the [rawpy API](https://letmaik.github.io/rawpy/api/) as a comparison for
   useful RAW workflows, not an interface to reproduce. Prefer Julia conventions,
   explicit lifecycle rules, and copied results over exposing borrowed pointers.
4. Document non-trivial functions with their purpose, accepted inputs, required
   state, result ownership, and examples where useful. Give simple helpers/types
   concise descriptions and link native counterparts to precise LibRaw sections.
   Keep autogenerated ABI files untouched by manual documentation edits.
5. Add focused regressions for behavior changes, especially ownership, error
   recovery, crop/CFA phase, and repeat rendering. Run the checks relevant to the
   change; a successful docs build is not evidence of camera-format coverage.

- Follow [Diátaxis](https://diataxis.fr/): tutorials teach through a guided lesson,
  how-to guides solve specific tasks, reference describes the API, and explanation
  develops understanding. Keep each focused on its reader's need and cross-link
  related material. Assume familiarity with Julia and Pkg. Explain RAW concepts
  and wrapper behavior without narrating basic Julia workflows.

## Ownership and lifecycle invariants

- High-level results must survive `recycle!` and `close!`. Immutable struct fields
   do not make contained arrays or dictionaries immutable.
- Preserve the processor with `GC.@preserve` while dereferencing native pointers.
   Use generated field offsets; avoid loading enormous native structs wholesale.
- Buffer input is copied and rooted by the processor; caller-owned IO stays open.
- Recycle restores native output defaults before a new open/unpack. Rendering
   also restores defaults before applying a complete `ProcessingParams` value.
- Fatal native failures invalidate managed state. Reject unsupported state
   transitions before calling C. Close is idempotent; processors are not safe for
   unsynchronized concurrent use.
- Native character arrays contain bytes: reinterpret signed `Cchar` values rather
   than numerically converting them to `UInt8`.
- Julia image arrays use row/column[/channel] order. Native row pitch is in bytes.
   CFA and thumbnail indices in the high-level API are one-based.
- JPEG previews contain encoded bytes; bitmap previews contain pixel arrays.
   Native JPEG width/height may be zero. Do not assume both result types have
   identical fields.

## Development and validation

Julia 1.12 is the declared minimum. `make deps` instantiates the root and `tools/`
environments. The latter contains Clang, Documenter, and JuliaFormatter.
The package is not registered in General yet. User-facing installation examples
must use `Pkg.add(url="https://github.com/yikerman/LibRawWrapper.jl.git")`.

- `make test`: package regressions; `make test-examples`: all runnable examples.
- `make check`: dependency setup, package loading, tests, and examples.
- `make docs`: docstring coverage, doctests, links within the manual, and HTML.
- `make format`: Julia source formatting; generated bindings are excluded.
- `make generate`: regenerate all six committed platform bindings, then inspect
  `git diff -- src/raw.jl src/bindings`. Test committed bindings before generation
  so regeneration cannot conceal stale shipped files; CI follows that order.

Generation downloads cross-platform header/toolchain artifacts. If Julia spends
excessive time optimizing the generator, `julia -O0 --project=tools gen/generator.jl`
has completed successfully with identical output. Generation alone does not
validate native execution on each platform.

The test fixture `test/data/test.nef` is a Nikon D850 image tracked with Git LFS.
Use LFS checkout for real image bytes; do not replace it with a pointer or alter
it for unrelated changes. Current fixture coverage does not validate X-Trans,
monochrome, float, or multichannel camera files. `snapshot(...).maker_notes`
currently contains placeholder values; detailed vendor fields remain raw-only.

## Repository conventions

Use short commit subjects matching the existing history, such as `fix: ...`,
`fix(ci): ...`, and `test: ...`. Keep independent changes in separate commits and
include regressions with the corresponding fix. Preserve intentional user edits;
in particular, the README beta-scope section was deliberately removed.

The wrapper is LGPL-3.0-or-later. `COPYING` contains GPLv3 and `COPYING.LESSER`
contains LGPLv3; keep this conventional naming and the README links in sync.
